# 062 LAR v3: notes from chat, note edits, quizzes, long answers

**Status:** building (parts A–D merged 2026-11-27, #368–#373; the screens are spec 063)

## What changes for the student

LAR can turn a chat into a real note and change notes the student already has, always behind a card they check first, with Undo. Decks become quizzes with multiple choice, true or false and identification, using wrong answers LAR writes. When the student asks LAR to explain or teach, the answer can run long, and "Keep going" continues it.

## Direction and references

The owner, 2026-11-26: "enhance the feature of the ai where it can actually make notes just from talking to it, edit notes if needed, and also like better quiz generation and long meaningful messages if needed." The owner took every recommended answer in both rounds of questions, plus "make it efficient": each action is one model call, and the phone does no work the student didn't ask for.

Spec 021 (IntAssis v2) and spec 055 (the study game) hold, except where a criterion below says otherwise. ADR 0003 holds: the rules pick the action, the schema forces its shape, and the model never proposes an action on its own. Nothing is written until the student taps.

## Keep

- Short notes: "Note: bring calculator" still makes a one-line note card (021).
- Reminders, flashcards from a topic, a note or a PDF, and the exact Due, Classes and Grades answers.
- Ask AI inside a note (Summarize, Tidy, Explain, Ask), unchanged.
- Flash, Type and Choice modes, which still work on cards with no wrong answers (Choice falls back to other cards' backs).
- The open tutor's stops (injection, self-harm, cheating, other people's data) and the "from what I know" label.
- Refusing to delete or rename reminders, events and decks from chat (`cannot_change`), now limited to those three.

## Behaviour

### Which request wins

- **C0. Order.** The rules read a message in this order, and the first that fits wins: a note edit (B, which never fires on a message naming a reminder, cards or a quiz), then a reminder, then cards or a quiz (C), then a note (A, the chat note when it names the chat), then the exact Due, Classes and Grades answers, then an open question (D). "Gawan mo ako ng quiz sa note ko" is a quiz, "remind me to fix my note" a reminder, "add a note that the exam moved" a new note. The add rule: "add a note", "new note", "make a note", "note:" and the like start a new note; "add X to my … note" or "add X" with a note open adds to that note (Append).

### A. Notes from chat

- **C1. Two kinds of note request.** A note request that names the chat ("make a note of this", "save what we talked about", "gawan mo ng note ito", "note this down") makes a **full note**. Any other note request makes the short note it makes today. The rules decide which (`intent.rs`), not the model.
- **C2. What a full note holds.** A title (at most 8 words), a subject (one of the student's subjects, or none), and a body of 3 to 12 bullet points that keeps the chat's own terms, facts and numbers. It holds only what the chat said: nothing new, nothing about LAR or the chat itself ("we talked about…").
- **C3. What it reads.** The turns of this chat, newest first, up to 6,000 characters. If older turns didn't fit, the card says so (Copy).
- **C4. One call.** A full note is one model call of at most 500 tokens, forced by a schema (`title`, `subject`, `bullets`).
- **C5. The card.** It shows the title, the subject chip and the whole body, with **Save** and **Edit**. Save writes a new `note:` note. Edit turns the title and body into fields on the card, so the student can change them before anything is kept. A card left alone saves nothing.
- **C6. Checked before it is shown.** A number, a date or a course code in the note that isn't in the chat is removed, along with the bullet that holds it. So is a bullet about the chat itself ("LAR explained…", "The student asked…"). If no bullets are left, the reply is the "couldn't make a note" line (Errors), not an empty card.

### B. Note edits

- **C7. The edit request.** "Change the exam date in my COMP note to Friday", "add the formula to this note", "fix the spelling in my Math note", "rename this note to Midterm review", "move this note to MATH 101", "delete my note about heaps". The rules read the verb and pick one of Append, Change, Tidy, Rename, Move or Delete.
- **C8. Which note.** The open note, if one is open. Otherwise the rules look for the words of the request among the notes' names, subjects and texts, a name match counting three times a text match. No search model is needed, so it costs no model call. With one clear match (or a top score at least twice the next) LAR uses it. With two or more, LAR lists the top four as buttons; a tap asks the same request again about that note. With none it says so (Errors). It never guesses.
- **C9. Change is line edits.** The model sees the note with numbered lines and returns only the lines to replace, insert or remove (`{"edits": [{"op": "replace" | "insert" | "remove", "line": n, "text": "…"}]}`). It doesn't write the whole note out again, so long notes stay fast. The app applies the edits. An edit pointing at a line that doesn't exist is dropped, and if every edit is dropped, or the note comes out unchanged, the reply says so.
- **C10. Append.** The model writes only the new lines, which go at the end. A line the note already has is dropped. The chat's last two turns go in only when the request points at it ("the formula you told me").
- **C11. Tidy.** Reuses Ask AI's Tidy (`note.rs`) on the whole note, so it has one prompt, not two.
- **C12. Rename, Move, Delete** need no model call. The title and the subject come from the request: the subject must be one of the student's subjects, or LAR asks for its code. Only `note:` notes can be renamed or moved; class and day notes keep theirs. A delete names one note: "delete all my notes" is refused. A note with photos is deleted from the note itself, not by LAR.
- **C13. The card.** Before and after, line by line: removed lines struck through, added lines in gold, unchanged lines dimmed and collapsed past three. Rename and Move show old and new. Delete shows the note's title and first lines, under "Delete this note?". The buttons are **Apply** and **Cancel**.
- **C14. Undo.** Applying keeps the note as it was before (the `note_undo` table). The applied card turns into "Changed · Undo". The note's own menu shows "Undo LAR's change" until the student edits the note themselves, which clears it. Undo after a delete puts the note back with its key, title, subject and pin. Only LAR's last change to each note is kept.
- **C15. Size.** Change and Append work on notes up to `MAX_NOTE` (3,000 characters). A longer note gets the "too long" line (Errors). Rename, Move and Delete work on any note.

### C. Quizzes

- **C16. Wrong answers on the card.** A card may carry three wrong answers (`Card.wrong`). A card without them still plays every mode as today.
- **C17. Made with the cards.** "Make a quiz on recursion", "make a quiz from my notes", "gawan mo ako ng quiz sa trees", and **Make a quiz** on the deck page (from a note or a PDF) make a deck whose cards carry wrong answers. The cards are written as today (batches of 12, retry at 6, duplicates dropped), then their wrong answers, 8 cards per call. One call for both was measured slower and broke (docs/ai.md). If the wrong answers fail, the cards are kept.
- **C18. "Quiz" against "due".** "Make", "create", "gawa", "gawan" or "generate" before "quiz" in the same message makes a quiz. "When is the next quiz?" is still a Due question.
- **C19. Wrong answers are checked.** Four are written; the first three that pass are kept, each checked against the right answer and the ones kept before it. One passes if it is a plain statement, isn't the right answer or a copy of it (the same meaning words in any order, or one is the other with words left out in the same order, with as many "not"s), isn't another wrong answer in the set by the same test, doesn't name the front's term, and is between a third of the right answer's word count and twice it plus two. A near miss ("toward less dissolved substance") is fair. A card with fewer than three that pass keeps its front and back and drops the wrong answers.
- **C20. Old decks.** A deck with four or more cards and no wrong answers shows **Write wrong answers** on the deck page. It works in batches of 8 cards per call, shows "N of M" cards while it runs, and can be stopped; what is done is kept.
- **C21. Quiz mode.** The deck page gets **Quiz** next to Flashcards, Type it and Choices. It is on with 4 or more cards. A card without wrong answers takes three other cards' backs, as Choice does, so a deck where LAR's wrong answers mostly failed still quizzes. A Quiz session deals each card as one of three, picked at random per card and never the same three times in a row:
  - **Multiple choice:** the front, with the back and its three wrong answers in random order.
  - **True or false:** the front with either its back or one of its wrong answers (half and half). Answering also shows the right answer.
  - **Identification:** Type mode on that card.
- **C22. Scoring.** Quiz scores, times, heats and schedules exactly as Choice and Type do (055 C3 to C6). True or false is timed like Choice.

### D. Long answers

- **C23. Length follows the question.** A question with "explain", "teach", "walk me through", "step by step", "in detail", "summarize", "compare", "outline", "ipaliwanag", "turuan" or "paano gawin" gets a **long** answer: up to 800 tokens. Every other open question stays **short**: 420 tokens, as now. The rules decide.
- **C24. A long answer reads as one.** It opens with the answer itself, uses short paragraphs or a numbered list where steps are asked for, and ends when it is done, not when it runs out. A long answer has no character cap. Short answers keep the 600-character cap (`REPLY_MAX`) they have today.
- **C25. Keep going.** A long answer that hit its limit shows **Keep going** under the bubble. It continues the same bubble from where it stopped for up to 400 more tokens, at most twice, and only on the newest answer. The continuation sees the question and the answer so far, not the facts again (`assis::more`), so it costs one short prompt. The stored turn gets the longer text.
- **C26. A bigger window when the phone has room.** The chat model loads with an 8,192-token window if the memory check (`models::gate`) passes with it, which costs about 250 MB more for Qwen3.5 2B (about 470 MB for Qwen3 1.7B, whose cache grows with every layer); the check uses each model's own figure. Otherwise it loads at 4,096, where a long answer is 400 tokens and Keep going is still offered. The prompt budget for facts and notes (`PROMPT_BUDGET`) doesn't grow, so the first word comes as fast as today.
- **C27. Streaming.** A long answer streams word by word, as open answers do now. Stop works at any point and keeps what came (before, a stopped reply ended in an error), with Keep going offered.

### Efficiency (all parts)

- **C28. One call per action.** A full note, an edit, a batch of 8 sets of wrong answers and a long answer are each one model call. Rename, Move, Delete, Undo and the choice of note take none. No action runs a second model pass to check itself: the checks are rules (C6, C9, C19).
- **C29. Nothing in the background.** No wrong answers, notes or edits are made until the student asks. Writing wrong answers stops when the app is hidden and continues from the next card when it comes back.

## Data shape

- `crates/intportal-ai/src/intent.rs`: `about_chat(msg)` tells a note of the chat from a note with its own text (no new intent: it is a kind of Note). Edits need no new intent either: `edit::kind(msg, note_open)` reads `Append | Change | Tidy | Rename | Move | Delete` first. `Intent` gains `Quiz`. Also `fn length(msg) -> Length { Short, Long }`.
- `crates/intportal-ai/src/assis.rs`: `Proposal` gains `SaveNote { title, subject, text }`, `EditNote { key, kind, before, after }`, `RenameNote { key, title }`, `MoveNote { key, subject }`, `DeleteNote { key }`, `MakeQuiz { topic, count }` and `PickNote { candidates: Vec<(key, name)>, ask }`. `Answer` gains `more: bool` (Keep going is offered); `assis::more` writes the next part. The shell gets `ai_more` and remembers the loaded window (`models::window`, `models::WIDE_CTX`).
- New `crates/intportal-ai/src/chatnote.rs`: `make(llm, tpl, chat, subjects) -> Option<ChatNote>`. `Facts` gains `chat`, every (student, LAR) pair of the chat, filled by the shell only for a note request.
- New `crates/intportal-ai/src/edit.rs`: `LineEdit`, `apply(text, &[LineEdit]) -> Option<String>`, and the prompt and schema for Change and Append.
- `crates/intportal-ai/src/gen.rs`: `Card` gains `wrong: Vec<String>` (`serde(default)`), `check_wrong`, `quiz` and `wrong_for(cards)`.
- `crates/intportal-core/src/store.rs`: a `note_undo` table (one row per note), `LarChange`, `lar_change`, `undo_lar` and `undo_keys`. The student's own `set_note` clears the row. Shell commands `lar_note_change` and `undo_lar_note`; `NoteItem` gains `undo`.
- `crates/intportal-core/src/study.rs`: `Card` gains `wrong: Vec<String>` (`serde(default)`). Backups carry it.
- `crates/intportal-ai/src/models.rs`: `Model` gains `n_ctx_low: u32`, the fallback window.
- `src/lib/assis/apply.ts`: the new proposal kinds and Undo.
- `src/lib/StudySession.svelte`, `src/lib/DeckPage.svelte`: Quiz mode (UI role, handoff).

## Errors

- No note matches: "I couldn't find a note about that. Open it and ask again."
- The note is too long to edit: "This note is too long for me to edit at once. Open it and select the part."
- The edit changed nothing: "That didn't change anything in the note."
- A full note came out empty: "I couldn't make a note from this chat. Try asking for it in a few words."
- Quiz cards, or wrong answers, failed: what arrived is kept, with "Made {n} of {m}. Try again for the rest.".
- The model isn't loaded or runs out of memory: 021's errors, unchanged.

## Motion and Reduce Motion

Cards use the chat's existing card entrance. The before-and-after card doesn't animate its lines. True or false uses Choice's right and wrong motion (055). Reduce Motion follows 055.

## Accessibility

Struck and gold lines also say "Removed:" and "Added:" to VoiceOver and TalkBack. True and False are full-width buttons at least 44 pt tall. Keep going and Undo are real buttons with labels. The note picker is a list of buttons.

## Out of scope

- In-app voice or a microphone button (the keyboard's dictation works).
- "Quiz me" in chat, asking one question at a time.
- Deleting or renaming reminders, events and decks from chat.
- More than one Undo step per note.
- Any cloud model.
